# 核心名词解释

本工具用于测量“音频输出 → 麦克风”的延迟（以麦克风接收为准）。以下是核心术语。

## 测量与信号

| 名词 | 解释 |
|---|---|
| 声学往返延迟 | 扬声器发出声音到麦克风收到声音的时间差（不含播放器启动开销的理想值，量级几十 ms）。 |
| 输出→麦克风延迟 | 本工具实际测量的“扬声器发声 → 麦克风拾音”延迟，含 DAC、声波传播、麦克风采集链路。loopback 模式可直接得到该值。 |
| 播放缓冲 | 播放器（ffplay/SDL/WASAPI）从“开始播放”到“扬声器真正发声”之间的内部缓冲。旧模式会把这段一起算进去，导致数值偏大（本机约 550~700 ms）。 |
| 播放缓冲偏移 | loopback 可用设备上 `含缓冲 − 延迟` 的差值，即纯播放缓冲部分。loopback 不可用的设备用它扣除。 |
| 相对有线延迟 | 蓝牙设备“输出→麦克风”减去有线设备“输出→麦克风”的差值，即蓝牙相对有线多出的延迟。 |
| 前导静音 (leadSilence) | 播放文件开头预留的静音，用于覆盖 ffplay 启动与蓝牙链路唤醒，防止 chirp 被吞掉。 |
| chirp / 线性调频信号 | 一段频率随时间线性扫动的测试音（默认 500~8000Hz，0.5s），便于互相关定位。 |
| 含缓冲测量 | 以“播放启动→麦克风”计时的测量，结果含播放缓冲；loopback 模式下每次播放同时可算出。 |
| dBFS | 数字音频相对满量程的电平。结果里“峰值 X dBFS”用于判断麦克风是否收到足够响的声音。 |
| 中位数 | 多次测量排序后取中间值，比均值更抗个别异常值。首次各测 3 次，后续 loopback 3 次 / mic 5 次取中位数。 |

## 检测算法

| 名词 | 解释 |
|---|---|
| 互相关 (cross-correlation) | 用已知 chirp 模板在录音里滑动比对，找出 chirp 出现的位置。 |
| FFT | 快速傅里叶变换，用来在频域做互相关，把长录音的定位计算降到 O(N log N)。 |
| GCC-PHAT | 相位变换加权的互相关。白化幅度谱、只保留相位，对蓝牙/扬声器高频衰减等“频谱整形”不敏感，定位更准。 |
| 归一化相关 (NCC) | 衡量录音里的波形与模板相似度的指标（0~1）。本工具使用去均值版本（demeanNcc）。 |
| 峰值显著性 (significance) | 相关峰值与本底噪声的比值。用于判断“确实录到了 chirp”，是有效性主判据。 |
| 质量 (quality) | 即去均值 NCC，辅助判据，排除波形完全无关的窄带干扰。 |
| 有效判据 | 默认 `显著性 ≥ 20` 且 `质量 ≥ 0.05`；loopback 结果还要求 loop 通道 `质量 ≥ 0.5`。 |
| 亚样本插值 | 在相关峰值附近用抛物线插值，得到亚样本精度的到达时刻。 |

## 系统与实现

| 名词 | 解释 |
|---|---|
| WASAPI loopback | Windows 自带能力：抓取“系统正在播放的音频流”本身。用它能拿到扬声器发声前一刻的参考，自动消掉播放缓冲。 |
| AUDCLNT_E_UNSUPPORTED_FORMAT (0x88890008) | loopback 初始化失败。常见原因：默认播放设备是蓝牙耳机，Windows 不支持对蓝牙 A2DP 端点做 loopback。 |
| dshow | Windows DirectShow 采集接口，ffmpeg 用它枚举/录制麦克风。 |
| ffplay / ffmpeg | FFmpeg 的播放器与编解码工具。本工具用 ffmpeg 录音/解码，用 ffplay 播放测试音。 |
| ffplay 音频时钟 | ffplay `-stats` 输出的播放进度（M 值）。用它给“chirp 开始播放”打墙钟时间戳，可消掉 ffplay 进程启动延迟。 |
| A2DP / SBC / AAC | 蓝牙音频传输协议与常见编码。A2DP 端点通常不支持 loopback；编码也会让 chirp 波形失真，所以用 PHAT + 显著性判据。 |
| SEA | Node 官方单可执行文件打包方案，用于生成 `latency.exe`。 |
| 差分法 (--reference) | 先测有线基线，再测蓝牙，两者相减抵消相同偏置，得到相对净延迟。 |
